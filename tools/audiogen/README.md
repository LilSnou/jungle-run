# tools/audiogen — чиптюновый рендер Jungle Run

Порт «живого» синтеза игры из Web Audio (JS) в чистый Python (только stdlib:
`math`, `wave`, `array`, `random`, `os`, `sys`). Ничего в `web/` не изменяется —
`web/js/core/AudioManager.js` остаётся источником истины.

## Как перегенерировать

```bat
cd <корень репо jungle-run>
python tools\audiogen\render.py
```

Python 3.10+ (проверено на 3.14), сторонние пакеты не нужны. Скрипт сам создаёт
`godot/assets/audio/music/` и `godot/assets/audio/sfx/`, рендерит всё (~3–5 с),
печатает отчёт по каждому файлу (длительность, частота, каналы, биты, пик) и
заново открывает каждый WAV для валидации.

## Что выводится

| Файл | Что это |
|---|---|
| `music/jungle.wav` | трек джунглей, 132 BPM, C-минор (луп, ~47 c) |
| `music/village.wav` | трек деревни, 112 BPM, F-мажор, том-барабаны `t` (луп, ~47 c) |
| `music/temple.wav` | трек храма, 150 BPM, D-минор + arp-канал (луп, ~48 c) |
| `music/victory.wav` | фанфара `play('victory')`, без лупа, 3.2 с |
| `sfx/jump.wav`, `doublejump.wav`, `slide.wav`, `coin.wav`, `heart.wav`, `stomp.wav`, `hurt.wav`, `fall.wav`, `gameover.wav`, `start.wav`, `biome.wav`, `click.wav` | все эффекты `play(name)` из JS |

Формат: **mono, 16 бит, 22050 Гц**, пик ≤ **0.89** (общий множитель на категорию
«музыка» / «эффекты» — максимальный пик категории ровно 0.89, относительная
громкость файлов сохраняется, клиппинга нет).

## Что портировано «один в один»

* осцилляторы `square` / `sawtooth` / `triangle` + белый шум через `bandpass` (Q = 1.2);
* огибающая `#tone`: атака 8 мс (0.0001 → vol, экспонента), экспоненциальное
  затухание до 0.0001 к концу ноты, «хвост» 0.0001 ещё 0.02 с
  (`osc.stop(t + dur + 0.02)`);
* `glideTo` — экспонентный скан частоты в течение всего `dur`;
* огибающая `#noise`: vol → 0.0001 экспонентно за `dur`, без атаки;
* степ-секвенсор `#schedule`: шаг `60 / bpm / 4` (16-е ноты), петля из 16 шагов,
  длительности каналов `bass = step·1.8`, `lead = step·0.9`, `arp = step·0.7`;
* барабаны `k` (0.09 c, 400→80), `h` (0.03, 9000→6000), `s` (0.14, 4000→900),
  `t` (0.11, 900→150);
* паттерны треков и все эффекты `play()` — дословные копии из JS;
* гейны `master 0.9`, `musicGain 0.42`, `sfxGain 0.75`. Особенность JS
  сохранена намеренно: `#noise` жёстко подключён к `#sfxGain`, поэтому
  **барабаны музыки идут через 0.75, а тона — через 0.42**.

## Особенности реализации

* **Тики.** Игровой цикл JS — `requestAnimationFrame` с `dt ≤ 0.05`, но аудио к
  кадрам не привязано: Web Audio планирует в секундах (`setInterval(25)` +
  упреждение 0.14 с лишь сдвигают вывод, а момент ноты `nextTime += stepDur`
  накапливается точно). Поэтому шаг синтеза здесь — реальные секунды
  (`stepDur = 60/bpm/4`), квантайзинга 1/30 или 1/60 нет.
* **Луп без обрыва.** Хвосты последних нот (bass тянет 1.8 шага) сворачиваются
  в начало буфера — слуховой эквивалент бесконечного лупа секвенсора в игре.
* **Зацикливание.** Рендерится целое число паттернов (`TARGET_LEN = 48 c`,
  минимум 2 полных цикла): jungle 26, village 22, temple 30.
* **Детерминизм.** Шум — `random.Random(0x4A554E47)`, рендер воспроизводим.
* Волны намеренно «наивные» (без сглаживания от алиасинга) — так ближе к
  железу NES/ChipTune, как и в исходном замысле.
